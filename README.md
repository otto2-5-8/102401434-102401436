## 二、与 Figma 原型的逐屏对照

## 三、与原型的三处必要差异（如实说明）

1. **首页标签是真筛选**：原型的 `Z-01首页-寻物信息` 与 `Z-01首页-招领信息` 两个状态帧内容完全一样
   （都放着「蓝色校园卡」和「黑色折叠伞」两张卡），也就是原型里切标签只动滑块、不换内容。
   HTML 里做成真筛选：默认停在「寻物信息」，首条卡片与原型 01 屏第一条逐字一致；切到「招领信息」显示招领数据。
2. **原型自身前后不一致，我以 01-首页为准**：01 屏把「蓝色校园卡」画成「状态：寻找中」（寻物），
   而 03/04 屏把同名物品画成「招领｜待认领」。我统一成首页口径（蓝色校园卡 = 寻物/寻找中），
   因此结果页里这条显示「寻物｜蓝色校园卡」（原型写的是「招领｜蓝色校园卡」）；
   详情页 08（黑色折叠伞·招领）、09（校园卡·寻物）与原型逐字一致。
3. **分类统一补齐为六类**：原型首页 5 个入口、搜索页 4 个选项，但示例数据里存在「生活用品」
   （黑色折叠伞、灰色水杯、白色围巾），原型两处都没有它的入口——点分类就找不到这条信息。
   所以首页入口、搜索页筛选项、发布表单下拉统一为六类（校园卡／钥匙／电子产品／书籍／生活用品／其他）。
4. **首页分类入口改成原地筛选**：原型里这几个入口是跳「03-搜索结果页」的热点；
   按使用反馈改成**原地筛选首页列表**：点一下只看该分类、选中的入口高亮、再点一下取消，
   分类结果立刻可见；搜索结果页仍由「首页搜索框 → 02-搜索页 → 搜索」这条链路进入。
   顺带修掉一个真 bug：原先点分类会把分类条件写进搜索状态，导致之后搜「校园卡」出现 0 条。

另外，原型里没有的**动态态**由我补齐（都属于需求 §5.2/§7.1 要求的"提示"）：必填项错误提示、
无结果空状态、操作结果 Toast、图片预览、上传区显示文件名。
示例数据共 18 条：前 7 条内容取自原型出现过的信息，另外 11 条是为了让**每个分类都有 3 条**
（点分类能立刻看出效果、不会只有孤零零一条）而补的同类示例；其中「白色蓝牙耳机」「黑色折叠伞」
标记为 isMine，与原型 07-我的发布页的两张卡片一致。

开发过程中端到端脚本抓到过 3 个真 bug 并已修复：`showView()` 里调用了不存在的 `refreshSearch`（搜索不生效）、
「我的发布」按日期排序导致顺序与原型不一致（改为按最近发布在前）、
首页点分类会把分类条件串进搜索状态导致后续搜索为 0 条（分类改为原地筛选，不再写搜索状态）。

## 六、数据模型

沿用框架字段：`id / type / name / category / location / date / status / description / contact`
（`type` 取 `lost` / `found`），存储键仍是 `campus-lost-found-items`。
我新增三个**可选**字段，缺省不影响另一位同学那半：`image`（图片 dataURL）、`isMine`（是否本人发布）、
`createdAt`（发布时刻，用于同一天排序）。示例数据里「白色蓝牙耳机」「黑色折叠伞」标记为 `isMine`，
与原型 07 屏的内容一致。
